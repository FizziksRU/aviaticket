# avia-bot

Цена авиабилета «здесь и сейчас» в Telegram, без LLM: обычные скрипты.

```
/price Москва Алматы 10.12
   │
   ▼
parsing.py     город/дата → Query(MOW, ALA, 2026-12-10)
   │
   ▼
pipeline.py    для каждого сайта из config/sites.yaml:
   ├─ source: api      → parsers/travelpayouts.py   (HTTP-запрос, без браузера)
   └─ source: browser  → телефон DroidHub (droidhub.py), если задан DROIDHUB_URL и phone в sites.yaml,
                         иначе collector.py (Playwright) → парсер из parsers/ по реальному JSON сайта
   │
   ▼
formatting.py  Telegram (HTML): лучшая цена, топ-5 по каждому сайту, ссылка
```

## Источники

Включены шесть сайтов с живой выдачей: aviasales, kupibilet, tutu, yandex_travel, onetwotrip, ozon_travel (`config/sites.yaml`). В проде они собираются на Android-телефонах через DroidHub: телефон открывает выдачу в Chrome и отдаёт перехваченные JSON-ответы сайта. Без DroidHub те же сайты открывает desktop-Playwright, но часть из них (ozon) отдаёт ему заглушку антибота.

**aviasales_cache** (Travelpayouts Data API) выключен по умолчанию (`enabled: false`). Нужен бесплатный токен из кабинета Travelpayouts (раздел API). Это кэш поисков Aviasales за последние ~48 часов, а не живая цена, поэтому в сообщении всегда есть ссылка на живую выдачу. Цена в API за одного пассажира, бот умножает на число пассажиров.

## Телефоны (DroidHub)

В `.env`: `DROIDHUB_URL`, `DROIDHUB_TOKEN`, `DROIDHUB_DEVICES` (id телефонов через запятую). В `sites.yaml` у сайта `phone: <id>` закрепляет его за телефоном, `phone: auto` берёт любой свободный из `DROIDHUB_DEVICES`. На один телефон идёт один запрос за раз. Если JSON не перехватился, бот один раз повторяет сбор. Замеры времени и надёжности по парам «сайт × телефон» — `docs/audit/02_droidhub.md`.

## Живые цены с сайтов (браузер + парсер)

Playwright открывает выдачу, сайт сам запрашивает цены JSON-ответами, и бот забирает именно их. Это надёжнее разбора вёрстки, но формат ответа у каждого сайта свой, поэтому парсеры пишутся по реальным данным. Порядок для нового сайта:

1. Снять шаблон URL выдачи руками и вписать в `config/sites.yaml` (у Aviasales уже есть).
2. Разведка: `python -m avia.recon aviasales Москва Алматы 10.12 --show`. В `debug/recon/aviasales/` появятся все JSON-ответы страницы, `index.txt` со списком (самые похожие на цены сверху), `page.txt` и скриншот.
3. Прислать мне эту папку, я пишу парсер в `src/avia/parsers/` (`@register_parser("aviasales")`) и тест на ваших данных.
4. В `sites.yaml` поставить `parser: aviasales`, `enabled: true`.

Если сайт покажет капчу, пройдите её руками при запуске с `--show`: сессия сохранится в `state/`.

## Установка и запуск

```bash
cd aviaticket
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp .env.example .env     # минимум TG_BOT_TOKEN и TG_ALLOWED_IDS; остальное описано в файле

export PYTHONPATH=src                    # пакет лежит в src/, без этого python -m avia.* не найдёт модуль
python -m avia.cli Москва Алматы 10.12   # без Telegram
python -m avia.bot                       # Telegram-бот
pytest                                   # тесты (pythonpath задан в pyproject.toml)
```

## Необязательно: LLM как запасной разбор

Для сайта, у которого парсера нет или он ничего не нашёл, в `sites.yaml` можно поставить `use_llm: true`: страница уйдёт в LLM. По умолчанию выключено. Бэкенды (`LLM_BACKEND` в `.env`):

- `gemini_local`: установленный на Маке `gemini` CLI.
- `agy_ssh`: аккаунт пула на своём сервере (`AGY_SSH_HOST`, `AGY_SSH_KEY`, `AGY_ACCOUNT`). Вход Google лежит на сервере, поэтому текст страницы отправляется туда по SSH, где обёртка `deploy/avia-llm` запускает `agy` под профилем этого аккаунта и его исходящим каналом. Обёртку нужно один раз положить на сервер (путь — `AGY_WRAPPER`, `chmod 755`), аккаунт на это время поставить на паузу в панели пула, затем проверить `python -m avia.smoke`. Обёртка запускает `agy` без `--dangerously-skip-permissions`: текст чужих сайтов недоверенный, а у пользователя `pool` есть доступ к токенам пула. Smoke-тест проверяет это «канарейкой».

## Что стоит знать

- **Условия сайтов.** Автоматический сбор выдачи может нарушать их пользовательские соглашения, а антибот-защита может блокировать. Для личного мониторинга небольшими объёмами это рабочий вариант. Travelpayouts Data API это официальный путь.
- **Парсеры ломаются при смене сайта.** Это цена отказа от LLM: если выдача перестала разбираться, бот пишет «0 вариантов» или ошибку по этому сайту, остальные источники продолжают работать. Тогда снова `recon` и правка парсера.
- **Доступ.** По умолчанию бот отвечает только id из `TG_ALLOWED_IDS` (администраторы, без лимитов). С `TG_OPEN=1` он отвечает всем в личных сообщениях: люди регистрируются в `storage/users.sqlite`, у каждого `DAILY_SEARCH_LIMIT` поисков в сутки (по умолчанию 40) и одна подписка. Администратор видит сводку командой `/stats` и закрывает доступ командами `/block <id>` и `/unblock <id>`.
- **Мощность.** Все поиски, включая опрос подписок, идут через общую очередь (`MAX_PARALLEL_SEARCHES`, по умолчанию 2), а каждый сайт собирается не чаще раза в 30 секунд. На двух телефонах это ~50 поисков в час; расчёт и симуляция — `docs/audit/03_capacity.md`.

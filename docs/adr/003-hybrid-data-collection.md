# ADR-003. Гибридный сбор данных: дешёвый предфильтр для подписок, телефон для живой цены

**Статус:** предложение.
**Дата:** 2026-11-03.

## Контекст

Один поиск стоит ≈96 с телефонного времени в одну сторону и ≈190 с туда-обратно (`02_droidhub.md` §3). Подписки опрашиваются каждые 30–60 минут (`subscriptions.py:151`), и каждый опрос — полный поиск на 6 сайтах. Живой Search API Aviasales недоступен: Travelpayouts открывает его только проектам с подтверждёнными 50 000 MAU. Data API доступен бесплатно, но это кэш поисков пользователей Aviasales: окно 48 часов, хранение 7 дней. Travelpayouts рекомендует его для статических страниц, а не как живую цену.

## Решение

1. **Подписки:** перед полным поиском спрашивать Travelpayouts Data API (`prices_for_dates`) по маршруту и дате. Полный поиск на телефонах запускать, только если:
   - кэшированная минимальная цена изменилась больше чем на X% с прошлого опроса;
   - или прошло больше T часов с последнего полного поиска (страховка от устаревшего кэша);
   - или до вылета меньше 7 дней.
2. **Живой поиск:** телефоны остаются источником истины.
   - Порядок: сначала дешёвые и быстрые источники (kupibilet, tutu, ozon на подходящем телефоне), выдача частями.
   - Эксперимент (только после согласования с владельцем и не нагрузкой): прямой вызов JSON-эндпоинтов kupibilet `/frontend_search` и tutu `/avia/offers/v2` с куками сессии, полученной телефоном. Если антибот это пропускает, телефон нужен раз в N минут для обновления сессии, а не на каждый поиск.
3. **Кэш выдачи** по маршруту, дате и сайту общий для всех людей. TTL по источнику: 5 мин для живых сайтов, 1–2 ч для Data API.

## Альтернативы

- **Больше телефонов.** Линейная стоимость, нагрев, обслуживание; не решает проблему фоновых опросов, только отодвигает.
- **Только Data API.** Не живая цена: расхождения с реальной выдачей, данных нет по редким маршрутам.
- **Aviasales Search API.** Недоступен до 50k MAU.

## Последствия

- Нагрузка подписок на телефоны падает в разы. Насколько, зависит от X и T; для ступени 50 нужен замер на реальных маршрутах.
- Появляется зависимость от Travelpayouts (токен уже предусмотрен, `TP_TOKEN`) и логика «доверия» кэшу.
- Прямые вызовы JSON — юридически и технически серая зона: условия сайтов, антибот, баны IP. Решение о них принимает владелец.

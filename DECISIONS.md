# Решения, принятые без владельца

Формат: дата (UTC) · решение · причина.

1. **2026-11-03 · Форк в `FizziksRU/aviaticket`.** `gh` залогинен как FizziksRU, а не pazrabi, поэтому по брифу сделан `gh repo fork`. Апстрим подключён как `upstream`, push в него не делается.
2. **2026-11-03 · Секреты держит процесс владельца, агент `.env` не трогает.** В `~/.claude/CLAUDE.md` (Tier 3) чтение и запись `.env` и токенов запрещены без исключений. Поэтому:
   - `.env` создаёт `tools/setup_secrets.sh`, который запускает владелец;
   - агент работает в отдельном worktree `~/avia-scale/work`, где `.env` нет, так что ни бот, ни CLI, ни тесты агента его не читают (`load_dotenv(ROOT/.env)` ищет файл в корне worktree);
   - в Telegram отчёты уходят через `tools/tg_relay.sh`, который запускает владелец. Агент кладёт текст в `~/avia-scale/outbox/pending/` (`tools/report.sh`), а «стоп» из Telegram превращается в файл `~/avia-scale/STOP`;
   - `tools/tg.sh` и `tools/notify.sh` созданы по брифу, но агент их сам не запускает;
   - проверка секретов перед коммитом (`tools/secret_scan.sh`) идёт по шаблонам токенов, а не по значениям из `.env`.
3. **2026-11-03 · Tier 2 (файлы, коммиты, `pip install` в venv) считается подтверждённым брифом,** но только внутри `~/avia-scale`, только в ветках `scale-audit*` и только с сообщениями в тестовый бот владельца. Причина: бриф прямо запрещает вопросы после шага 0.
4. **2026-11-03 · Телефоны считаются общими с боевым ботом**, бюджет не больше 40 `fetch_page` в час. Причина: на вопрос про DroidHub в `setup_secrets.sh` владелец не отвечал (DroidHub через MCP), поэтому выбран консервативный вариант.
5. **2026-11-03 · DroidHub только через MCP `pool-avia`**, без HTTP-клиента бота с токеном. Владелец подтвердил: «pool-avia он как раз и нужен». Следствие: реальный `avia.cli` через телефоны не запускается. Путь «телефон → парсер» проверяется так: снимки снимаются через MCP `fetch_page` с теми же параметрами, что шлёт `droidhub.py`, а затем прогоняются через тот же код пайплайна на локальном моке DroidHub.
6. **2026-11-03 · venv на Python 3.12 через `uv`.** Системный python3 = 3.14 слишком свежий, а проект требует ≥3.10.
7. **2026-11-03 · Тесты и CLI запускаются без `ALL_PROXY/HTTP(S)_PROXY`.** На машине задан системный SOCKS-прокси, httpx подхватывает его из окружения и падает без `socksio` (22 падения). Это особенность окружения, а не кода. Отдельной находкой в техдолг идёт то, что тесты не изолированы от окружения.
8. **2026-11-03 · Фаза 1 начата, пока ждём relay.** Фаза 1 не зависит от Telegram.
9. **2026-11-03 · Telegram Web недоступен в этой сессии.** Встроенная проверка безопасности auto mode блокирует браузер. Сквозной прогон диалога делается через мок Telegram Bot API (фаза 3).
10. **2026-11-03 · Тестовый бот только для тестов приложения, отчёты в него не шлю.** Так сказал владелец. Журнал ведётся в `PROGRESS.md`. Боевой прогон приложения на этом боте возможен только через шлюз `tools/tg_gateway.py`: его запускает владелец, а агент `.env` не читает (см. #2).
11. **2026-11-03 · Для замеров в фазе 2 после 20:20 `max_chars=3000` вместо 200000.** Ответы без перехваченного JSON приходят целиком в контекст агента и забивают его. Парсеры работают по JSON, а текст нужен только для проверки «страница непустая» (>200 символов), поэтому исход разбора от этого не меняется.

Каждая ветка отходит от `scale-audit`, для прогона «после» есть интеграционная ветка `scale-audit-all`.
